---
title: "Schedule SMS"
description: "Send an SMS later, change its delivery time, or cancel it"
---

Set `scheduled_at` to queue an SMS now while delaying its delivery job until a future time.

## Schedule a message

For a new send, `scheduled_at` accepts an ISO 8601 timestamp or a relative value such as `in 5 min`:

```bash
curl --request POST \
  --url https://api.dugble.com/sms \
  --header "Authorization: Bearer $DUGBLE_TOKEN" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: <unique-request-key>" \
  --data '{
    "to": "+233201234567",
    "from": "Dugble",
    "body": "Your appointment starts in one hour.",
    "scheduled_at": "2026-08-05T11:52:01.858Z"
  }'
```

Supported relative units include seconds, minutes, hours, and days. The resolved delivery time must be at least 30 seconds in the future.

## Update the delivery time

Use `PATCH /sms/{message_id}` while the message remains queued and outside the delivery cutoff. Updates require an ISO 8601 timestamp; relative values are not accepted.

```bash
curl --request PATCH \
  --url https://api.dugble.com/sms/49a3999c-0ce1-4ea6-ab68-afcd6dc2e794 \
  --header "Authorization: Bearer $DUGBLE_TOKEN" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: <unique-request-key>" \
  --data '{
    "scheduled_at": "2026-08-05T13:00:00Z"
  }'
```

## Cancel a scheduled SMS

```bash
curl --request POST \
  --url https://api.dugble.com/sms/49a3999c-0ce1-4ea6-ab68-afcd6dc2e794/cancel \
  --header "Authorization: Bearer $DUGBLE_TOKEN" \
  --header "Idempotency-Key: <unique-request-key>"
```

Dugble changes the SMS state to `canceled` and removes its pending delivery event in the same database transaction.

## Scheduling rules

- Initial schedules must be at least 30 seconds in the future.
- Rescheduling and cancellation are blocked during the final 15 seconds before delivery.
- Only queued messages with a future `scheduled_at` value can be changed or canceled.
- Processing, submitted, delivered, failed, and already canceled messages cannot be changed.
- Use a unique `Idempotency-Key` for every distinct mutation.

<Warning>
    Schedule time is not a delivery guarantee. Provider and carrier processing
    can add latency after Dugble releases the message for delivery.
</Warning>
